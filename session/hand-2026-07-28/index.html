  2. 02Proposal — "The First Real Task": stop proving mechanisms in isolation, wire them together

    Decision-record, no code. Names the accumulated pattern across EPIC-P0 and EPIC-P1: every mechanism — scheduler, context switch, pools, IPC, spoor, the PE64 loader, the Win32 shim, real fault handling, per-task CR3 switching — was proven in its own isolated Tier 0 fixture and never wired together; the real (non-fixture) boot path still only discovers ACPI/PCI topology and halts, dispatch::run_once calls plain switch with no CR3 awareness, and spoor has exactly zero production call sites despite four completed Stories building it. Proposes folding a real integration into the already-next-scheduled STORY-P1-03-02: give dispatch::run_once CR3 awareness, schedule the real blue-sharc.exe (already proven loadable via blue-sharc-fixture) as an actual task under its own real, W^X-correct address space, let a real defect in its own capability-boundary code (not a hand-placed ud2) fault and be contained live, and give spoor its first production call site auditing that event. Everything this needs already exists as Verified mechanism except dispatch::run_once's own CR3-awareness — the smallest new code that could make this claim real. Three open questions left for the user: fold into -03-02 or split into a new Story; which capability boundary is the real fault trigger; whether the real boot path's ending changes or gains a second branch.

  3. 03Pre-implementation hardening review of STORY-P1-03-02 — nine defects, three fatal

    A review of the Story's finalized acceptance criteria against the actual code, before any code was written. Nine defects (D1–D9), three fatal as written: the capability-fault criterion conflated three mechanisms none of which actually faults; the W^X claim omitted the kernel's own all-RWX boot map and would have passed vacuously with CR0.WP/EFER.NXE unset anywhere in the codebase; and a per-entry W^X audit would have passed while the loader's own writable staging alias defeated W^X entirely. Criteria rewritten before implementation. Kept as the worked example of the review standard this project now expects.

  4. 04STORY-P1-03-02 Verified — W^X, sealing, teardown, and the first real task

    TinyOS ran something. blue-sharc.exe — a real, externally-authored executable — parsed by the real PE64 loader, mapped into its own real W^X address space, and scheduled as a genuine task through the production CR3-aware dispatcher. Its own MSVC CRT reached for GetSystemTimeAsFileTime, a capability it did not hold, faulted on an NX instruction fetch, and was contained — the first fault this project has caught from a real workload's own defect rather than from a fixture built to fault on cue. Also: the boot-time all-RWX identity map is retired at run time, loader aliases are sealed, teardown is generation-safe, and spoor gains its first production call sites. Contains a retracted flake diagnosis (see Handover 05).

  5. 05STORY-P1-03-03 Verified — import resolution, the system image, and the D04 switch cost

    Re-reading Handover 04's own passing capture showed its containment was arithmetically accidental: nothing had patched the loaded image's IAT, so a refused capability jumped to an unrelocated RVA that merely happened to land on non-executable memory. Fixed: every IAT slot is now written exactly once at load time — granted imports get real, callable extern "win64" trampolines, everything else gets a deliberately-unmapped trap address that names the cause in CR2. Also delivers the top-level os system image crate (the real boot path finally loads and schedules a task) and the twice-deferred D04 measurement. Retracts Handover 04's boot-timeout "flake": the real cause was a PowerShell argument-splat defect in the regression sweep, and the timeout loosening it nearly justified was reverted.

  7. 07Proposal — process memory confidentiality and integrity against a memory dump

    Scoping document, no code. Takes "make a process memory dump undecipherable" as the goal and argues the originally-suggested mechanism (decode-on-access for all process memory) is aimed at a different adversary. States a five-row threat model first, and corrects the central assumption: layout randomization does not defeat a dump — an offline analyst scans rather than guesses. Recommends R1–R5 in priority order with the RT carve-out "encode at rest; never on the live working set", since decode-on-fault collides directly with kernel::fault having no Resume arm. Revised in place by Handover 08’s eight requested changes — it now carries §4b (key lifecycle), §4c (power states), §4d (the publication test), the reordered recommendations, declared metrics, and the downgrade-attack objection.

  8. 08Review of the confidentiality proposal, and the construction that follows

    Reviews Handover 07 against the Sharc.Blue evidence base and finds its central hole: 07 specified the AEAD construction with care and never said where the key lives. Against an offline analyst holding a dump that buys approximately nothing, because the dump contains the key next to the ciphertext. Supplies the missing section — a TPM-sealed per-machine root_secret with per-process keys derived on demand from public process metadata as salt, derive-use-wipe rather than hold-resident — plus the power-state analysis showing hardware memory encryption alone fails at the first hibernate, and Kerckhoffs’s test as the cleanest way to tell a real mechanism from a decorative one. Also: copy Sharc.Blue’s KeyRing, not its ten-layer Oracle Mono pipeline, which never shipped into a production path and is obfuscation stacked on AES-GCM.

  9. 09STORY-P1-04-01 Verified — timer-driven preemption, extended state, and inversion avoidance

    This kernel preempts. A task whose body contains no switch, no hlt and no scheduler call ran ~1.3M iterations, was taken off the CPU by a real local-APIC tick, and resumed exactly where it was for another ~420k. kernel::dispatch was not modified — a preempting tick switches into the same dispatcher_ctx run_once is already suspended at. Closed LE-14, but not where it was scoped: the adversarial XMM0 check failed with the save/restore on the preemption path, because an interrupt handler is itself compiled code on the interrupted task's stack and a non-preempting tick clobbers SSE just as thoroughly, so FXSAVE/FXRSTOR moved into the ISR stub — then the omission was deliberately falsified to prove the check can fail. Closed LE-01: the three-task inversion scenario runs for real, with the medium task Ready throughout and frozen at zero while the boosted holder finishes. Opens LE-20; LE-02 untouched, so FEAT-P1-04 does not exit.
