  11. 11STORY-P1-04-02 Verified — WCET enforcement on the real timer

    A task that exceeds its declared WCET budget is caught by real time and has the consequence it declared at creation applied to it — restarted from its entry point, degraded beneath a real competitor, or tripped to a fail-closed safe state. The policy is a parameter of create_task with no default (78 call sites), a degrade floor above the task's own priority is rejected rather than clamped (an overrun must never be a route to a criticality level nobody granted), and kernel::fault::Disposition is deliberately not extended — an overrun has no frame, no vector and no hardware event, so it gets a parallel decision table that likewise reads exactly one input, the declaration made in advance. Detection landed on the offender's 5th attributed tick against a budget of 4 in all three runs. Closed LE-02. The finding: all three Tier 0 fixtures passed first time and two proved nothing — a falsification removing every enforcement mutation left wcet-restart green (it was proving its own context rewind, not the kernel's budget-window reset) and wcet-trip reporting ok=true (it never checked the task was Finished, and since its pass condition is a failure exit code, exit 1 carried no information). Opened LE-22.

  23. 23BCM2712 / Raspberry Pi 5 divergence record — where Pi 4 material is wrong, and how each one fails

    The reference document TEST-P1-07-01-A clause 7 asks for, split out of the session handover because the next four Stories will keep reopening it. Every row names how it fails, not just what it is. The debug UART is uart10 at 0x10_7D00_1000 — a 35-bit address, and truncating it to 32 bits does not fault: it lands on 0x7D00_1000, ordinary DRAM on every Pi 5 SKU, so a Pi 4 habit writes UART configuration into memory, reports success, and the line stays silent. The reference clock is a fixed 9.216 MHz, not the Pi 4's configurable 48 MHz, and it divides exactly at 115200 (IBRD = 5, FBRD = 0) — whose second-order trap is that a wrongly-computed fractional divisor still works on this board and breaks everywhere else, so the arithmetic is tested against both clocks. os_check=0 or the firmware loads the image at 0x200000 instead of 0x80000, and that is the one constant here with no test behind it, because config.txt is on an SD card. Also: the GPIO-header UART has no fixed-address Pi 5 equivalent (RP1, over PCIe); unaligned access with the MMU off faults rather than being slow, which is why the target spec keeps +strict-align and the softfloat ABI; and what a Pi 4 source gets right — the PL011 itself is ARM's PrimeCell and transfers unchanged. Carries the build recipe, including that -Z build-std=core alone leaves memcpy/memcmp undefined at link time.

  29. 29Next-session mandate — two decisions are owed before any more ARM64 code

    The start-here document written at the close of this date. This session wrote no kernel code; it ran an architectural analysis, an expert code audit and a commercial review through the register, and ends with nine new rows (LE-33..LE-41) and two open decisions that block scheduled work. LE-39: ADR 0004's premise does not hold. Its load-bearing sentence is that interrupt masking at EL1 means what it says, and against GICv3 Group 0 / Secure Group 1 interrupts routed by SCR_EL3.FIQ it does not — secure-world interrupts preempt NS-EL1 irrespective of PSTATE.I, unattributably. That is structurally the same hole the ADR disqualifies x86_64 for. Recommended repair is ADR 0005 superseding 0004 and applying 0004's own falsifiability test to ARM64: the real-time tier becomes conditional on per-platform secure-world qualification rather than automatic. Bare-metal EL3 was considered and rejected — Pi 5 firmware owns EL3. LE-41 is the only deadline in the register: Cargo.toml declares MIT and no LICENSE file exists, and relicensing is possible only while authorship is single-source — a window that closes permanently on the first outside contribution and announces nothing when it does. Two of six audit findings did not survive contact with the code and are recorded as corrected: LE-37's CPACR_EL1 trap cannot fire today (the target spec is softfloat/-neon, so no SIMD is emitted — the real defect is a build flag standing in for a hardware init), and LE-40 is not the reported TOCTOU (page-table translation under a shared borrow on one core, no C4 mutation path) but is a .expect() on a kernel path resting on an unstated SMP assumption. LE-38 is LE-04 on a second architecture — no emergency fault stack, the defect x86 closed with TSS/IST. LE-22 gains the fix shape it lacked: dynamic effective priority, not a stored restore.
