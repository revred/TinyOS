  1. 01STORY-P0-07-03 Verified — grant fails closed instead of panicking

    LE-40's remedy line reserved a Story for "replacing the .expect with a fail-closed path… before any SMP work". Auditing the whole function for that defect class found a worse instance than the row named: grant computed every page address with unchecked +/* on caller-chosen values, so a page-aligned sharee_virt of 0xFFFF_FFFF_FFFF_F000 — which passes both the alignment and the kernel-region checks — overflowed on the second page. Unlike the .expect, that is reachable today, and the release build is worse than the debug build: with overflow-checks defaulted off the address wraps silently to 0x0 and is never re-checked against KERNEL_RESERVED_REGION_END, because the function is already past that check. Both profiles set panic = "abort", so the debug disposition is a whole-system abort on a transactional path. A second finding the row also did not name: the mapping loop's re-read .expected presence and re-checked permissions not at all — so under the same conditions it would have panicked on a vanished page and mapped a narrowed one anyway. The privilege-escalating half was the unguarded one. Presence and authority are now one verdict from one function that both loops call; the range is checked once up front (SharedMemoryError::RangeOverflow); the generation counter refuses to wrap or saturate (it is the whole basis of StaleGrant); and a test gates this module's non-test source against explicit panic constructs, failing on the pre-fix source and naming the line. Host tests 613 → 621. LE-52 registered for the generalisation — with the warning that the implicit half is where this session's reachable defect actually was.
