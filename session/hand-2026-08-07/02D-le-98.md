## 1. Item 1 — `EPIC-P1`'s `FEAT-P1-11`, and it was missing in a third place

`01C` said two places. There were three, and the third is the one that would
have been left behind:

- the **Features table** jumped `FEAT-P1-10` → `FEAT-P1-12`;
- the **`Status:` header** enumerated Features and stopped at `FEAT-P1-10` —
  missing `FEAT-P1-11` **and `FEAT-P1-12`**, which the table already carried.

Both now read through `FEAT-P1-12`. The `FEAT-P1-11` summary is taken from that
Feature's own header rather than re-derived, and it states the three gaps as
gaps: criterion 3's `Skipped`/`Failed` arms are host-only, the round's cost with
interrupts live is **unmeasured** and is a different number from the fixture's
masked one, and there is one task with no preemption, no `EL0` and no
containment claim.

Carried unactioned through four handovers, so it is worth naming why it
survived: it is not code, no gate reads it, and every session had something in
front of it. `check-assurance-spine` counts 138 status headers and cross-checks
98 Feature/Story rows — **it does not check that an Epic enumerates its own
Features**, which is why prose drift in the one place a reader starts survived
four mandates. That is a gate-shaped gap and it is recorded here rather than
built, because building it is the next section's problem in miniature.

## 2. Item 2 — stopped, and the reason is a machine-checked contract

`01C` queued *"`LE-98`'s remaining half — the device-tree parse that makes
`SIMPLEFB_BASE` evidence rather than folklore"*, inherited from `LE-98`'s owner
path, which says **"a device-tree parse is the fix that ends the argument."**

The boot path is ready for it: `hal_arm64::boot::Handoff` already captures `x0`,
which is the DTB pointer under the AArch64 Linux boot protocol, and reports it.
Writing the parser was the obvious next move.

**It is forbidden, in three places that agree with each other:**

- [`FEAT-P1-07`](../../goals/features/FEAT-P1-07.md) §6 — *"A real DT parser is
  a hostile-format parser and belongs behind the Security Charter's `C4`
  discipline, not in a bring-up Story. This Feature hardcodes-and-verifies.
  That is exactly `BND-03` — `C1` contains no complex hostile-format parser —
  and it is the reason the non-goal exists (`PD-12`)."*
- The same Feature's **non-goals** list *"A device-tree parser."*
- [`class-communication-matrix.tsv`](../../goals/security/class-communication-matrix.tsv)
  — the `C1`→`C1` guarantee is **"fail closed without invoking a complex
  hostile parser"**, boundary test `BND-03`. `FEAT-P1-07`'s contract row selects
  `BND-03` and `PD-12` at implementation class `C0,C1`, and `hal-arm64` is `C1`.

`hal-arm64` is the only place the canvas could consume a parse today, so the
fix as written lands exactly where the contract refuses it. **Nothing about the
hazard is wrong** — a 4 MB write to a fixed physical address on a no-IOMMU
machine, on boots where a panel is merely *reported*, is still unjustified, and
`09C` narrowed it rather than closing it. What changed is that closing it is a
**Feature-sized, `C4`-contained** piece of work, which is design surface, and
the 2026-07-30 sprint rule has not been lifted. `01C` says so itself about a
different change on the same page.

Item (2) of `LE-98`'s remainder — the fault path's named exception at
`canvas::Canvas::last_resort_for_fault_report` — is blocked on item (1) for the
reason already recorded and is not independently closeable, so there was no
smaller half to take.

**`LE-98`'s owner path now carries the blocker and three options**, all the
owner's: file a `C4`-contained DT-parse Feature and lift the sprint rule for it;
find a non-parsing confirmation the firmware will actually answer — noting the
mailbox framebuffer **grant** is already known refused on this firmware
(`fb=refused`, `BOARD VERDICT 4`), which is the obvious candidate and is already
eliminated; or accept the narrowed hazard as stated debt and say so where the
constant is declared. **No code was written toward any of them.**

### Why this is the execution rather than a failure to execute

The priority ordering is *safety before security before correctness before
performance*, and the two candidate readings were: build a parser that violates
`BND-03` because a handover asked for it, or stop and report that two documents
disagree. A mandate does not outrank a contract, and `LE-98`'s sentence was
written without reconciling it against the Feature that owns the constant. This
is the same shape as `LE-91`: **a plausible instruction that the register
refuses**, found by trying to carry it out.

## 3. A mistake I made, and the rule that caught it in one tool call

Editing `LE-98`'s row, I replaced the tail of `owner_path` and re-appended the
four trailing fields — which were already there. The row went to **12 fields in
an 8-field file**.

`CONCURRENT_SESSIONS` rule 8 says validate a hand-edited machine-checked file
**before your next tool call**, with the check that would fail. `check-spine-files`
found it immediately and the row was repaired in the following call; the tree
was never left invalid for another session to trip over, which is the entire
point of the rule. It also surfaced that this row's `raised_in` is
`hand-2026-08-06/07C` with no trailing `session`, unlike its neighbours —
noticed only because the repair required reading the fields individually.
