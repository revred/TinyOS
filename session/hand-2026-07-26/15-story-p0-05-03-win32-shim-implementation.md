# Handover 15 — `STORY-P0-05-03` Implemented and Verified: Capability-Scoped Win32 API Compatibility Shim

Follows: [`14-story-p0-05-02-address-space-implementation.md`](14-story-p0-05-02-address-space-implementation.md), which implemented `STORY-P0-05-02` (process address-space creation/section mapping) and named `STORY-P0-05-03` as the natural next pick for `FEAT-P0-05`. This handover picks up that mandate directly.

## What this session did

1. **Resolved the open `aci`-ordering question** (flagged unresolved since Handover 11, restated in Handover 14). No `aci` crate exists in this workspace (Phase 5, per `docs/mvp-delivery-strategy.md`) — this Story's own text sanctions not blocking Phase 0 work on it, so this session defined the minimal capability-check shape standalone: the `CapabilityPolicy` trait in the new `exec::win32_shim` module. Every function that needs a policy decision takes `&impl CapabilityPolicy`, never a concrete policy type (Dependency Inversion) — the migration path once `aci` lands is additive (a new `aci`-backed implementor, wired in at call sites, no change to `resolve`/`check_imports`/the call implementations), documented in the module's own doc comment.
2. **Implemented `exec::win32_shim`** (new module, `os/src/exec/src/win32_shim.rs`):
   - `Api` — a closed, explicitly-enumerated set of 9 `KERNEL32.dll` calls (`GetCurrentProcess`, `ExitProcess`, `HeapAlloc`, `HeapFree`, `GetStdHandle`, `WriteFile`, `ReadFile`, `CreateFileA`, `CloseHandle`), sized to this Story's named categories (process/thread basics, heap allocation, file/console I/O) rather than any real `blue-sharc.exe` import table — no such binary has been sourced yet (open since Handover 11/12).
   - `resolve(dll_name, symbol_name) -> Option<Api>` — the single designated dispatch point permitted to know about every `Api` variant (`agent/CODING_STANDARDS.md`'s Open/Closed exemption for an unavoidable central dispatch point), kept thin.
   - `check_imports` — validates every import `STORY-P0-05-01`'s parser found against the allowlist before any code runs; the first non-allowlisted import is a load-time rejection (`ShimError::NotAllowlisted`), matching `pe::parse`'s/`address_space::validate_sections`'s own "first violation, no partial state" precedent.
   - `CapabilityPolicy` trait + `AllowAllPolicy` (the shipped default) — see point 1.
   - `Buffer`/`validate_buffer` — walks every page a buffer argument spans via `AddressSpace::translate`, failing closed with `ShimError::OutOfBounds` *before* any access, checking write-permission when the call needs it. This kernel still has no IDT/exception-handling subsystem (a gap `STORY-P0-05-02`'s handover already named), so this proactive check — not a fault caught after the fact — is the only enforcement mechanism available; mirrors the codebase's established validate-first, mutate-second discipline.
   - `write_file`/`read_file` — the two call implementations shipped this Story, chosen as the representative pair needed to prove allowlist dispatch + policy-gating + buffer bounds-checking end to end. Both check `CapabilityPolicy::is_granted` before anything else; `read_file`'s destination buffer must be mapped *writable* (the shim is about to write into it). Neither actually transmits/reads real bytes anywhere — this kernel has no console/serial or file-backing driver yet, a separate unimplemented subsystem, flagged in the module's own doc comment rather than silently assumed complete.
   - 10 new host tests (`#[cfg(test)]`), TDD-first per `agent/CODING_STANDARDS.md`'s mandate for security-relevant subsystems: allowlist recognition/rejection, import-table rejection/acceptance, a policy-denied call rejected (not degraded to a no-op), a buffer running past its mapped section rejected, a buffer pointing at the kernel's reserved region rejected, a read-only destination rejected for `read_file`, a well-formed call succeeding, and a zero-length buffer always in-bounds.
3. **Added a test-only `FixedBytes::for_test` constructor** (`os/src/exec/src/pe.rs`, `#[cfg(test)] pub(crate)`) so `win32_shim`'s tests can build `ImportEntry` values by hand without going through `pe::parse`'s full byte layout.
4. **Added the Tier 0 QEMU fixture**: a new `win32-shim-fixture` `[[bin]]` (`os/src/exec/src/fixture_win32_shim_main.rs`, following `exec-fixture`'s own established shape) and `xtask qemu-x86_64 --fixture=win32-shim`. ## What this session deliberately did not do

- **Did not implement a real audit log for policy denials.** `TEST-P0-05-03-A`'s own specification calls for "the denial is audited the same way any other ACI-mediated denial is" — there is no audit-log subsystem in this workspace, independent of `aci` itself, to route through yet. A policy denial today returns `ShimError::PolicyDenied` with no audit trail. Recorded as a gap in `TEST-P0-05-03-A.md`'s revision note, not silently treated as satisfied.
- **Did not wire in a real `aci`-backed `CapabilityPolicy`.** `AllowAllPolicy` is the only production-shaped implementor shipped; a real per-process, per-scope policy is `aci`'s job once that crate exists. The `DenyPolicy` used to prove the rejection path is test-only.
- **Did not implement call bodies for 7 of the 9 allowlisted `Api` variants.** `GetCurrentProcess`, `ExitProcess`, `HeapAlloc`, `HeapFree`, `GetStdHandle`, `CreateFileA`, `CloseHandle` resolve and are capability-checkable but have no implementation — only `write_file`/`read_file` do, as the minimal pair needed to prove the mechanism. Adding the rest is additive (new functions following the same `CapabilityPolicy`-check-then-`validate_buffer` pattern), not a redesign.
- **Did not implement a real console/serial or file-backing driver.** `write_file`/`read_file`'s bounds-checking is real; the actual byte transfer is not — a well-formed call validates and reports success/byte-count without transmitting or reading anywhere. Flagged in `win32_shim.rs`'s own doc comment.
- **Did not induce/catch a real `#PF` for the out-of-bounds check.** Same reason as `STORY-P0-05-02`: no IDT/exception-handling subsystem exists yet. The out-of-bounds check is a proactive bounds walk against `AddressSpace::translate`, verified deterministically, not a live fault caught after the fact.
- **Did not implement `STORY-P0-05-04`** (end-to-end `blue-sharc.exe`) — the last remaining Story for `FEAT-P0-05`, now unblocked.
- **Did not source or vendor a real `blue-sharc.exe` fixture.** Still open from Handover 11/12 — unchanged. The 9-call allowlist is provisional and will need reconciling against the real image's actual imports once one is sourced.

## Key decisions worth restating

- **`CapabilityPolicy` is this Story's own answer to the `aci`-ordering question Handover 11 deliberately left open.** A local trait, not a concrete type, so a real `aci`-backed implementor is a drop-in addition later rather than a rewrite — the same Dependency Inversion pattern `hal_x86_64::paging`'s `FrameAllocator` trait already established for `exec::address_space`'s relationship to `kernel::mem::Pool`.
- **The out-of-bounds check is proactive, not fault-based, because there is nothing to catch a fault with.** `validate_buffer` walks every page a buffer spans via `AddressSpace::translate` before any access — the same validate-first, mutate-second shape `pe::parse` and `address_space::validate_sections` already use, applied one level up at the shim boundary. This is a structural consequence of the still-missing IDT, not an independent design choice.
- **Only two calls got real implementations, deliberately.** `write_file`/`read_file` were chosen because together they exercise both the read-only-buffer and write-required-buffer paths through `validate_buffer` — enough to prove the mechanism adversarially (per this Story's TDD mandate) without building out an implementation for every allowlisted call before any of them has been proven correct.
- **The allowlist is provisional, sized to this Story's named categories, not a real import table.** Sourcing `blue-sharc.exe` (still open) will likely require reconciling this list against its actual imports before `STORY-P0-05-04` can proceed — flagged explicitly rather than assumed to already match.
