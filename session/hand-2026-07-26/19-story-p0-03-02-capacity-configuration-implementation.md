Added `STATIC_MEMORY_BUDGET_BYTES` (8 MiB, matching `G-DX-8`'s existing image-size ceiling as the nearest reference point) and `committed_bytes()`, checked by a `const _: () = assert!(committed_bytes() <= STATIC_MEMORY_BUDGET_BYTES, ...)` — a capacity that would overflow the budget fails the build with a `const`-evaluation error (`error[E0080]`), not a runtime allocation-failure path.
2. **Wired the consolidation through**: `kernel::main` now imports `MAX_CPUS` from `kernel::capacities` instead of defining it locally; both `exec` fixture files now import `EXEC_FRAME_POOL_CAPACITY as FRAMES` from `kernel::capacities` instead of each declaring their own `FRAMES` constant.

Discovered along the way that `cargo doc` does *not* fail the same way (rustdoc doesn't force the same const-evaluation) — deliberately left unasserted rather than treated as a bug in the fixture, since that's an accident of rustdoc's own implementation, not something this Story's acceptance criteria care about.
4. **1 new host test**: `capacities::tests::committed_capacities_fit_within_the_documented_budget` — a runtime-visible restatement of what the `const` assertion already enforces at compile time, making the property visible in `cargo test`'s own output rather than only inferable from the build having succeeded at all.

## What this session deliberately did not do

- **Did not declare a task-control-block, IPC-message, or demand-paging pool capacity.** This Story's own description names all three as eventual consumers of this location, but none has a real production call site yet — no `Scheduler` is wired into `main.rs`'s boot path (`STORY-P0-02-05`'s dispatch loop is real, but nothing calls it from `kernel_main`), and no IPC or demand-paging subsystem exists at all. Adding a placeholder constant with nothing to consume it would be speculative, ahead-of-need code this codebase's own standards argue against — flagged as future work for whichever Story first wires a real consumer in, not silently pre-built here.
- **Did not implement byte-exact accounting for `committed_bytes()`.** It multiplies each capacity by its element type's `size_of`, ignoring `Option`/`MaybeUninit` tag/padding overhead in `Topology<N>`/`Pool<T, N>`'s own internal layouts — adequate headroom for a ceiling check at Phase 0's sizes, documented as approximate rather than claimed exact.
- **Did not measure `STATIC_MEMORY_BUDGET_BYTES` against real hardware.** 8 MiB was chosen to match `G-DX-8`'s existing image-size ceiling as the nearest available reference point, since no Tier 2 target hardware has been purchased yet — flagged as worth revisiting once it is.
- **Did not implement `STORY-P0-05-04`** (end-to-end `blue-sharc.exe`) — still blocked on sourcing a real binary, unchanged from Handovers 11/12/15–18.

## Key decisions worth restating

- **Only capacities with a real call site were consolidated — the Story's own "one reviewable location" framing was interpreted literally, not aspirationally.** `MAX_CPUS` and `EXEC_FRAME_POOL_CAPACITY` are the only two that exist as concrete, non-test values anywhere in the workspace today; adding aspirational placeholders for named-but-not-yet-built subsystems would have inverted the anti-speculative-generality principle this codebase otherwise holds to throughout.
- **The compile-time budget check was proven with a governance fixture, not just asserted to work.** Mirroring `fixture-oversized`'s existing precedent for the LOC-ceiling gate, `fixture-capacity-budget` is a self-contained crate independent of `kernel::capacities` itself — the property worth proving generically is "this style of `const`-assertion actually fails a build," which doesn't need (and shouldn't depend on) any of `kernel`'s own current capacity values.
- **`cargo doc`'s behavior on a build-breaking crate was investigated empirically rather than assumed.** It doesn't fail the same way `cargo build`/`clippy` do — worth remembering for any future fixture that assumes all four gates (`fmt`/`build`/`clippy`/`docs`) always co-fail on a genuine compile error; they don't, and `fixture-capacity-budget`'s own check list reflects that rather than asserting something false.
