  1. 01AThe need for speed, and what must not be traded for it

    Written at the owner's request on the framing that the project now has a verifiable development cycle worth a 10× improvement, with TDD and no loss of quality. §2 — where the speed actually comes from: evidence replaced transcription; ground truth captured before design (twenty minutes of SSH sized STORY-P1-10-05 correctly and corrected a wrong risk statement already made out loud); a capture no longer has to be lucky; and gates that cost less than the failures they catch. The benchmark is real — STORY-P1-10-05 ran observation → ground truth → design → TDD → gates → Story → commit → image in about an hour, with the owner only inserting a card and applying power. §3 — what must not be traded, each with this session's receipt: prove the Red (14 tests failed against a neutered implementation); never substitute a constant for a discovery (LE-69 refused a conforming device, and a wrong temperature still reads like a temperature); state what you did not measure (LE-74's caution was right and far too gentle — the board measured two consecutive epochs 151 counter ticks apart); a gate that cannot see its subject is not a gate (LE-72); widen a vocabulary, never stretch one (and note ACT now has one verb of headroom). §5 — the mandate, and it is not what FEAT-P1-10's Story list implies: hal-arm64 references none of sched, dispatch, lock or wcet — the board has never run TinyOS's kernel. There are no call sites to wire because nothing calls them. The real next milestone is one task dispatched once on silicon, with the tick driving the dispatch round, observed through the stream built for exactly that. First, though: boot f06bfa8ac7ec and read the thermal rung, and write REPORT-2026-08-04-01, which is release-blocking.
