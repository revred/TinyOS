  1. 01AThe decomposition is code now, and the first instruction it refutes

    09A closed with a five-step mandate and one instruction for whoever wrote next: do not report x/460 without decomposing it. The decomposition is now a subcommand — cargo run -p xtask -- assurance-status, closing LE-84 — and the code's first act was to refute step 1 of the mandate that asked for it. 09A §8 step 1 said G09 could be filed "against the 8 MB image ceiling CI already computes… registration, not measurement". G09's target column reads "feature code plus read-only data delta <= 96 KiB" per domain; check-image-size measures the whole image against 8 MiB and names a different gate, G-DX-8. Three orders of magnitude apart, and it is 09A §5's own finding committed by 09A in the instruction telling the next session to avoid it — filed as LE-86. The ledger is now nested rather than subtracted, with a test asserting every parent equals the sum of its children, so the error that made 09A print 164 for 220 is unavailable rather than unlikely; §3's headline is a test (zero hardware-only gates in any implemented in-play domain — the board unblocks nothing on this register); and the decomposition is pinned to the authoritative spine walk so a second reader of the same TSVs cannot drift from the first. The register can finally say "measured, read against the target, and refused": evidence_kind is a closed vocabulary and refused is excluded from the count by construction, so STORY-P1-06-01's reasoned PERF-D03-G20 declination is a row instead of Report prose the next session would have re-filed. Evidence moved 20 → 21, not 22. G23's missing arm exists — the gate's target is a ratio and every spoor cost on record is absolute, so a paired spoor-enabled phase now runs in the same boot as its twin (two arms from two runs cannot answer a 2% question when BOARD VERDICT 9 measured ~3% build-to-build movement), held to "differs by exactly one stamp inside the timed region" by a source-level test. The actuation path reached the real-time architecture: hal_arm64::actuation drives eight RP1 bank-0 GPIOs as one byte-wide command bus through the XOR alias — one store, no SET-then-CLEAR transient, no branch on the data — filed as STORY-P1-06-02, with its glitch-ordering test seen to fail before it was trusted. Also: assurance.rs split from 4,482 lines into nine modules at the owner's instruction, where the split silently weakened a real guarantee and the guard written to catch that fired twice on its first two runs; and two scope decisions settled before the work — STORY-P1-05-01 gained D11 (free at prototype) while D12/D13 stay out, and both Features' exit criteria re-worded because FEAT-P1-05 asked for SEC-20 converting "for the Tier 0 scope", a state the spine cannot represent. Then the owner powered the board, and §7a is the result: PERF-D07-G23 has a number at last and it is +26.1% against a 2% target — both arms in one boot, parsed by the unchanged parser at metrics=12, recorded as the fail it is. The derived finding is the useful half: 2% of 479 cycles is 9.6, a stamp costs 137, so the budget admits one stamp per ~14 pool operations — G23 constrains instrumentation density, not stamp cost, and nothing had said so because no percentage could be computed before today. Four power cycles, and not one failed in the kernel: LE-87 (two tos64-netboot instances bound UDP 69 and the stale one won every TFTP request, so the board booted a stale image and emitted a complete, plausible, entirely wrong envelope while every visible signal said the run was good), LE-88 (the server refused /config.txt as a path traversal because Path.Combine discards the root, so pciex4_reset=0 never applied and the board reported confession code 2 — the kernel diagnosed the host tool precisely and a human went looking at the kernel), and LE-89 (the twelfth metric overran a hand-picked 2048-byte transcript, so the arm reached the wire carrying its name and none of its numbers). All three fixed or registered; the capacity is now derived rather than guessed. Still open on the board: STORY-P1-06-02 criterion 4 and LE-82, both needing a build before a boot.

  2. 02AThe label was the gate, and two bench tools lying by omission

    01A left a three-item mandate; items 1 and 2 are done and item 3 is deliberately not started, because the finding that came out of item 2 changes what item 3 is worth. The sentence to carry forward: a metric's domain label is not a name, it is the choice of which target column the number will be read against. Three spoor metrics were emitted as D07 — fixed-capacity pool allocation — when their subject is D11, "spoor stamp and journal", and the label was D07 for no better reason than that STORY-P1-10-02's contract selected D07: the metric bent to fit the contract instead of the contract extended to fit its subject. Those numbers sat on the wire for two days, quoted in a Report, a handover and the Story's own status header, and were never once compared to D11's targets. Read against them at last: PERF-D11-G01 p50 = 0.0571 µs against ≤ 0.03 — a fail by 1.90×, filed as one; PERF-D11-G02 p99 under by 0.7%, which is a quarter of the ~3% build-to-build movement BOARD VERDICT 9 measured, so filed refused rather than passed — a verdict that flips on a recompile is not a verdict; PERF-D11-G03 p99.9 met with 40% of room. The distribution is tight (min 131, p50 137, p99 143, p99.9 144), so the substrate's problem is its median, not its tail. Evidence 21 → 23 of 460; the mechanism that would prevent the next bent label is filed as LE-91, along with the reason the obvious check (fixture domains ⊆ owning Story's contract) is not the rule and would be wrong if asserted. LE-87 is closed: tos64-netboot binds both ports without SO_REUSEADDR in Main before any thread starts, exits 3 naming the holding PIDs, and logs the served file's full sha256 and absolute path per transfer — and the defect reproduced itself mid-fix, two more pre-fix instances holding UDP 67 and 69 simultaneously. The tool had no tests and now has 23, the first test project for any bench tool, including the platform semantic that made the defect possible; both detectors were seen to fail before being trusted, turning exactly five tests red. LE-90, found while verifying that fix and worth more than the bug it interrupted: redirected stdout is buffered at 4 KiB and flushed on exit, and a netboot server does not exit — so the bench log showed five banner lines and nothing after, including the digest line just added. That is LE-87's own cause one level down, and it makes the instruments four-for-four on failing by omission. And the density question 01A §7a raised is answered for free: the park loop's beat is 1 Hz and stamps about five times per second — ~685 cycles/s of a 2.4 GHz core, under one part in three million — with no pool traffic in the beat at all. The 26.1% stands as the fail it is, but it is a budget for whoever next stamps inside a hot loop, not a description of what the OS pays today. Added after the push: these three sessions were committed and pushed at the owner's instruction, and CI went red on a compile error every local gate was blind to — METRICS = 9 beside an eight-element [None, …] literal in the x86_64 measure fixture. Nothing local compiles the x86_64 kernel binary at all: check-boot-images builds AArch64, cargo test builds host tests, and the only thing that compiles src/kernel for its own target spec needs QEMU. That is LE-72's hole mirrored on the other architecture, filed as LE-92 with the fix costed at one subcommand; all 19 x86_64 variants were then built locally before the second push. The rule that caught it is LE-64's: push, then watch the run.
