The model

This folder is where TinyOS's goals become traceable, testable work — and stay traceable once they're built. It exists so that "does this Story actually verify a real Goal, and has it actually been tested?" has a written, checkable answer instead of a remembered one.

Status lifecycle

PLANNED defined, not started  ·  IN PROGRESS actively being worked on  ·  BLOCKED cannot proceed, reason stated explicitly  ·  VERIFIED Test(s) passed, Report filed

A Story is never Verified on implementation alone — only a passing Test with a filed Report earns that status.

Just-in-time decomposition

Only EPIC-P0 is decomposed to Feature/Story/Test level — it's the next real work. Decomposing every future Epic today would produce dozens of Story files describing undesigned work, which this project's own principles argue against. Decompose an Epic when work on it is about to start, not before.

Cross-cutting performance catalogue

625 performance guardrail tests cover 25 OS domains against 25 measurable latency, CPU-cycle, memory, allocation, queue, throughput, isolation, fault-containment, observability, footprint, and comparative-evidence checks. The complete machine-readable expansion is performance/catalogue.tsv; the current-state review records which Phase-0 surfaces exist and which future subsystems remain only specified or designed.

These cross-cutting contracts are intentionally not added to the Story/Test verification counts above: all 625 begin as Specified, not Verified, and become executable evidence only when the owning Epic/Story exists. Linux and “10× RTOS” comparisons are claim gates requiring same-hardware, safety-equivalent evidence, never assumed project facts.
