# STORY-P1-09-01 — The Kept Link: RP1 Presence as Evidence

Status: **In progress — host half Green 2026-08-03 (generated config pinned, probe gates and identity driven-rejected over the scripted seam, report line pinned); criterion 4 awaits a board capture. Not Verified.**
Feature: [`FEAT-P1-09`](../features/FEAT-P1-09.md)
Introduced in: [`session/hand-2026-08-03/05A-ethernet-discovery-signal.md`](../../session/hand-2026-08-03/05A-ethernet-discovery-signal.md), executing 04A's dependency chain on the owner's reorder

## Description

The Pi 5 firmware brings the PCIe x4 link to the RP1 southbridge up during its own
boot and resets it before handing off — unless `config.txt` says `pciex4_reset=0`.
This Story adds that line to the built card contents and teaches the kernel to
find out, honestly, whether the window survived — **without ever touching an
address that might not answer**. The probe interrogates the root complex before
the window: the PCIe2 controller's own registers live in the always-mapped SoC
block at `0x10_0012_0000`, so the kernel first requires the status register to
say *RC mode, PHY link up, data-link active*, then reads the outbound window
registers back and requires them to actually map CPU `0x1F_0000_0000` onto RP1's
peripheral space. Only a link that passes both gates earns the one read through
the window itself: the Ethernet block's module-identification register at CPU
`0x1F_0010_00FC`, validated against the Cadence GEM identity before it is
believed. The outcome — either way — is one `TOS64-LINK/1` line after the
verdict.

A board whose firmware reset the link (old EEPROM, a hand-edited card missing
the keep-line) fails the first gate and reports `rp1=absent reason=link` from
registers that always answer — no data abort, no hang. The residual risk that a
validated window still yields a completer abort on the final identity read is
named, not engineered away this Story: that abort takes the ordinary
`STORY-P1-07-02` fault-report path and parks fail-safe with the fault decoded —
diagnosable, never silent.

**No Ethernet traffic.** This Story neither configures the MAC nor touches the
PHY; it proves reachability of the block and nothing else.

## Acceptance criteria

1. **The card contents carry the keep-line.** The `xtask pi5` pipeline emits
   `pciex4_reset=0` in `config.txt`, the placement instructions state why, and
   the host-side tests pin the generated contents — including that the two lines
   `FEAT-P1-07` requires are still present verbatim.
2. **The probe is a pure decision over a scripted seam.** MMIO access goes
   through the `Mmio` seam scripted in host tests (`LE-66` discipline from
   commit one), and the probe's three gates are each driven Red-first: a status
   register missing RC mode, PHY link, or DL active; window registers whose
   readback does not map `0x1F_0000_0000` to RP1; and a module-identity answer
   that is all-ones (floating), all-zeros, or the wrong module — every one a
   distinct rejection resolving to `rp1=absent` with its reason.
3. **The report is one line and the protocol is unchanged.** `TOS64-LINK/1
   rp1=present id=0x…` (or `rp1=absent reason=…`) is emitted after
   `TOS64-RESULT/1`, and every pinned protocol line stays byte-identical.
4. **Board: both outcomes are diagnosable.** With the line present the capture
   shows `rp1=present`; with it deliberately absent the capture shows
   `rp1=absent` — no hang, no silent dark board, splash unchanged.
