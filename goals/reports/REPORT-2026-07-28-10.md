## Raw evidence

### Clause 1 — `LE-33`, provenance at the point of measurement

The envelope is now `TINYOS-MEAS/2`. A real Tier 0 run (`cargo run -p xtask -- measure --fixture=pool-bench --profile=release`) emits and re-parses:

```text
TINYOS-MEAS/2 BEGIN tier=T0 arch=x86_64 platform=qemu-tcg-x86_64 qualification=none
              cycle_source=rdtsc overhead_cycles=... cycles_per_us=...
```

The version digit was bumped rather than the keys quietly added: adding required keys is a breaking change, and a `/1` stream is one *missing provenance*, which must not be parsed and silently defaulted. The parser refuses `/1` and `/3` alike, refuses a `BEGIN` missing either new key, and refuses a `qualification=` value that is neither `none` nor a well-formed `REPORT-YYYY-MM-DD-NN` id — `qualification=pending` would otherwise travel in an envelope and read downstream as though a record existed.

`goals/assurance/qualified-platforms.tsv` registers five measuring platforms. **Zero are qualified, the Raspberry Pi 5 included**, which is `ADR 0005` decision 3 as a value rather than a sentence. A committed-tree test asserts that zero and fails loudly the day a platform is marked qualified without a Report to point at.

CI runs this job on Linux, where it passes. This Story did not change it and could not have caused it.
