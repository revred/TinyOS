**Deliberately not done:**

- **No real capability policy engine.** `aci` (Phase 5) doesn't exist in this workspace yet; `CapabilityPolicy` is this Story's own minimal standalone trait, with `AllowAllPolicy` as the only production-shaped implementor shipped so far (test-only `DenyPolicy` proves the rejection path). Migration path documented in `win32_shim.rs`'s own doc comment: a future `aci`-backed `CapabilityPolicy` implementor slots in at call sites with no change to `resolve`, `check_imports`, or the call implementations.
- **No audited denial log.** `TEST-P0-05-03-A`'s own specification calls for "the denial is audited the same way any other ACI-mediated denial is" — there is no audit-log subsystem in this workspace to route through yet (it doesn't exist independent of `aci` either), so a policy denial today only returns `ShimError::PolicyDenied`; the audit trail is a documented gap, not a silently skipped requirement.
- **No real console/serial driver.** `write_file`/`read_file`'s bounds-checking is real and enforced; the actual byte transfer is not, since this kernel has no console or file-backing driver yet. A well-formed, in-policy, in-bounds call validates its buffer and reports success/byte-count without transmitting or reading real bytes anywhere. Flagged in `win32_shim.rs`'s own doc comment, not silently assumed complete.
- **Only 9 `KERNEL32.dll` calls allowlisted**, chosen to match `STORY-P0-05-03`'s named categories (process/thread basics, heap allocation, file/console I/O) rather than any real `blue-sharc.exe` import table — no real `blue-sharc.exe` binary has been sourced yet (open since Handover 11/12), so this allowlist is provisional and will need reconciling against the real image's actual imports once `STORY-P0-05-04` sources one.
- **`HeapAlloc`/`HeapFree`/`GetStdHandle`/`CreateFileA`/`CloseHandle`/`GetCurrentProcess`/`ExitProcess` are allowlisted (resolvable, and rejectable-by-policy) but have no call implementation** — only `WriteFile`/`ReadFile` got one, as the two representative calls needed to prove the capability-scoped-dispatch and buffer-bounds-checking mechanism end to end. Implementing the rest is additive (new functions dispatching through the same `CapabilityPolicy`/`validate_buffer` pattern), not a redesign, but out of this session's scope.
