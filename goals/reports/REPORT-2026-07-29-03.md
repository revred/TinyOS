## Findings worth carrying

1. **The second authority layer the review did not name.** Upstream's `on_message` lets local
   app commands through *without consulting the ACL at all* when the app ships no ACL manifest
   (`webview/mod.rs` `has_app_acl_manifest` gate). Coherent with upstream's `local: true`
   posture; under TinyOS it is the same inversion one layer down. Closed for the resolver path
   (above); any non-resolver deployment must ship an app manifest.
2. **`MockRuntime` never emits `Destroyed`**, so the app-layer manager leaked bookkeeping on
   window close. Patched in the fork (both close paths), verified by upstream's own suite —
   upstreamable alongside the five `cfg(test)` sites that let the whole unit suite run with no
   platform webview stack (57/57 headless — of independent value to CI anywhere).
3. **The invoke key stays, for now.** Review §7.1's contingency is confirmed in practice:
   deleting the bearer secret before a transport carries kernel-derived identity removes a
   mitigation without supplying the boundary. It travels until the transport question is settled.
4. **Environment record:** builds use `rust-lld` + the cargo-xwin splat (no MSVC, no WebView2
   toolchain); `vswhom-sys` (a C shim that exists only to *locate* Visual Studio) is stubbed in
   pure Rust in the PoC workspace. Two `tauri-utils` **doctest executables** fail to *load*
   (`0xc0000139`, an xwin/system-DLL export mismatch) identically with and without the patch —
   machine-level, not a patch effect.
