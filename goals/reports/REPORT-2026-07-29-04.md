**Findings worth carrying:**

1. **`send_line` is honest about a one-way transport.** The verb is enumerated, resolves
   through the manifest — and then fails with a named error: the target kernel's serial driver
   is TX-only; there is **no UART RX path anywhere in the tree**, and no fixture reads input.
   13F §2.3's plan to live-verify the storage-free verbs by typing at a fixture is therefore
   not executable today. Registered as **`LE-55`**, with the repair path (serial-RX HAL story +
   an interactive echo-class fixture, landing with `EPIC-P2`'s shell work — 08C §4 forbade
   Stage E from adding fixtures).
2. **13F's named smoke fixture does not exist.** There is no `boot-banner` in the
   `qemu-x86_64` catalogue, and the default boot emits nothing on serial. The console's smoke
   fixture is `measure`, which emits the `TINYOS-MEAS/2` envelope. Recorded inside `LE-55`.
3. **Two new build-tooling stubs, the `vswhom-sys` pattern again** (owner's no-Microsoft-tooling
   rule): `rc_shim.rs` replaces the absent Windows Resource Compiler with a valid-empty-`.res`
   emitter, and `common-controls-v6` is off because without an embedded manifest the loader
   binds comctl32 v5 and `TaskDialogIndirect` dies with `STATUS_ENTRYPOINT_NOT_FOUND` — found
   the hard way, at process init. Neither touches a vendored crate.
4. **Toolchain pins leak through `cargo run`.** A cargo-spawned child inherits
   `RUSTUP_TOOLCHAIN`/`CARGO`/`RUSTC`, which breaks the TinyOS tree's pinned-nightly
   `-Z build-std` build with a harness error. The harness scrubs them; anything else that ever
   drives `xtask` from inside another cargo process will need the same six `env_remove`s.

## Result — Deliverable B: the terminal gap, measured

**Delivered:** [`docs/terminal-gap-analysis.md`](../../docs/terminal-gap-analysis.md) +
[`goals/context/terminal-gap.tsv`](../context/terminal-gap.tsv) — **33 rows** (22 canonical
verbs, 10 window behaviours, 1 transport row), every row carrying `msdos` / `linux` /
`windows_terminal` / `tinyos_decision` / `status` / `evidence`. The DOS column is read from
the actual `external/MsDOS` `v4.0/src` sources with file-path evidence down to exact message
strings; the Windows Terminal column likewise (`external/WindowsTerminal`); the TinyOS column
quotes the decided record only. Header restates the `EPIC-P2` §2 no-binary-compatibility
prohibition.

**Status discipline:** 32 rows `spec-level`, 1 row `live-verified` (the serial transport
asymmetry, demonstrated end-to-end by the Stage E console). 13F §2.3's plan to live-verify the
storage-free verbs is not executable today — `LE-55` (no shell, no serial RX, no interactive
fixture) — and the register says so rather than softening a status.

**Findings the spec table did not state** (now recorded per-row): `MOVE` does not exist in
MS-DOS 4.0 at all (the binding is a DOS-6-ism adopted for muscle memory); 4.0 `COPY` silently
overwrites — no confirmation prompt exists in `COPY.ASM`; `DIR` has only `/P`/`/W` (the
spec's `/S`↔`-R` adopts a later DOS-ism); `DEL`'s "Are you sure (Y/N)?" fires only on an
all-wildcard pattern; 4.0's exit codes are counter-examples twice (`FIND` documents
ERRORLEVEL 1 and never assigns it; `ATTRIB` discards its exit code entirely); `CLS` emits
`ESC[2J` when ANSI.SYS is present or stdout is redirected. On the window axis, the
`LE-53`(b) requirement is now evidenced from source: Windows Terminal's writer→renderer signal
is a relaxed atomic store, frames coalesce rather than queue, and every blocking wait sits
outside the buffer lock — the drop-frames-not-block shape TinyOS adopts and strengthens
(dropped frames are *reported*, and the tab host sits below the RT floor).

**Not yet machine-gated, deliberately:** wiring `terminal-gap.tsv` into `check-spine-files`
requires the two-sided invariant (fast-checked ⇒ also read by the full spine check), i.e. a
small `assurance.rs` validator first — named as next-session scope, exactly as 13F's "can be
gated later" anticipated.
