## The lines that carry the claim

**`line_writes=0` in the overrun run.** A decision that overran its declared budget produced **no
actuation at all** — on a write count the fixture keeps independently of the port's own bookkeeping,
incremented after the real `out` retires so it can never claim a write that did not happen.

**`late_probe=Some(Err(DeadlineMissed))` with `probe_writes=0`.** This is the difference between
prevention and unreachability. The overrunning task presented a command *with its own declared
identity, while it was still running*, after its deadline had closed and before the trip removed it —
and the port refused it. Without this probe the "late actuation is prevented" claim would rest entirely
on the offender never reaching an emit, which is not the same claim.

**`TRIP … attributed_ticks=13 budget=12 (bound 13) finished=true`.** The enforcement fired on the first
tick past the declared budget, took the `TripToSafeState` the task had *declared* (checked against the
declaration, not against whatever came back), and the kernel left the task `Finished` — a state change,
not a value the fixture chose to act on.

**`denial_phase_writes before=1100 after=1100`.** 1,100 emits presented with the background task's real
`TaskId`, every one refused, and the actuator line never moved.

## Clause 7 — the falsifications, and the three defects they found

Two falsifications, one per claim. Both fire, 3 runs of 3. **All three defects below were in the
*fixtures*, and every one of them would have shipped a green run that proved less than it appeared to.**

**1. The authority falsification passed — because the fixture was testing the wrong check.** With the
owner check removed from `ActuationPort::emit`, the `actuation` fixture still reported `ok=true`. The
background task is `Ready`, not `Running`, so the port's *separate* "the caller must be running" check
refused it anyway. The fixture was exercising the running check and reporting it as evidence for the
authority check. The intruder is now placed in `Running` for the denial phase, so the **only** thing
distinguishing it from the declared owner is its identity. The falsification then fires 3/3, with
`before=1100 after=2200` — 1,100 unauthorized commands reaching the actuator. (The host tests were
never fooled: four of them failed immediately under the same revert, because they set the intruder
`Running`. The Tier 0 fixture was the weaker instrument of the two, which is not the direction one
expects.)

**2. `preemptions=1311424` in a run that saw ten ticks.** An impossible number, and the same value
appeared as `overhead_cycles=1311424` in an earlier run's envelope. Both were spilled cycle deltas: the
control task's 8 KiB stack — every other fixture in this crate uses 8 KiB — overflowed **downward into
`.bss`**, because this is the only fixture that runs the measurement harness from task context
(`Stopwatch`, a `without_interrupts` closure per iteration, a thousand-sample `summarize`) in an
unoptimized profile, on top of the interrupt frame and the 512-byte `fxsave` area the tick hook lands on
the same stack. The symptom was not a fault; it was **plausible numbers in the artifact**. Stacks are now
32 KiB and carry a canary that is checked before any number is read as evidence, so the next occurrence
says so instead.

**3. The prevention falsification proved nothing, twice, for two different reasons.** First, the overrun
run could not detect an emitted late command at all, because the trip removes the offender before it
reaches any emit — hence the late-emit probe, which is clause 4's only Tier 0 instrument. Then the probe
stopped running: raising the tick rate (see below) collapsed the window between the missed deadline and
the trip to a single tick, and the probe never fired **in the honest build or the falsified one**. Both
"passed" the falsification identically, which is the failure mode a falsification exists to catch and
very nearly did not. The declared budget is now 12 ticks against a deadline of 2, which leaves ~10 ticks
between the two events wherever in a tick period the arm lands. With the expiry check removed the
overrun fixture then fails 3/3 with `late_probe=Some(Ok(()))` and `line_writes=1` — a late command
reaching the actuator, named.

## A fourth finding: the fixture proved nothing in release, and its own clause said so

At the inherited 500,000-count APIC reload, the **release** build completed all 2,200 iterations before
the *first* tick arrived: `ticks=0`, no deadline monitor exercised, and the run measured a path while
proving nothing about the mechanism it exists to demonstrate. Clause 1's own `ticks >= 1` check caught
it and failed the run rather than reporting the percentiles. The reload is now 50,000 and both profiles
see real ticks throughout — 74 in the dev run above. A fixture whose evidence depends on the optimizer's
mood is not a fixture.

Worth stating plainly: three of these four findings were caught by a check that existed only because the
Test document demanded it before the code was written, and the fourth by running the falsification the
document demanded rather than assuming it would fire.

## What is not claimed

- **The bound.** No `PERF-D03-G04` or `PERF-D05-G04` row is filed, and **the bound is stated debt against
  `LE-09`**. Under `ADR 0005` a worst-case bound is quotable only from a platform holding a secure-world
  qualification record, and zero platforms hold one — the Raspberry Pi 5 included. `xtask`'s
  `bound_provenance` check would refuse such a row, and it is right to. A QEMU-measured distribution is
  the mechanism's proof; the boards' numbers are the product's. The Story therefore records **no margin
  against a declared bound**, because no declared cycle-denominated bound exists to hold it to, and
  inventing one from this data is precisely what the ADR forbids.
- **`PERF-D03-G20`, which this Story does measure.** The denial path is exactly `G20`'s shape — a denial
  that must be cheap and change nothing — and the state half holds outright (1,100 refusals, zero
  writes). The latency half does not survive its own variance: run-to-run p99 CV of **55%** on the
  denial metric, on numbers whose absolute scale is a TCG device-model dispatch anyway. Measuring
  something is not the same as being able to stand behind a number for it, and a register row is a
  claim about a threshold. `PERF-D09-G20`'s precedent was a Tier 0 filing with a 2.8× margin and a
  stable measurement; this is neither.
- **The distribution under hostile load.** `FEAT-P1-05` has no Story started. The Feature cannot be
  Verified without it and its status now says so.
- **The shipping `os` image.** This path lives in fixtures, exactly the "proven in a fixture, not on the
  real boot path" shape `LE-20` tracked for WCET enforcement. **This is an unregistered loose end**: id
  contiguity is enforced and a concurrent session holds the next id in a written-but-uncommitted row,
  so this one cannot be allocated yet. It is owed the moment theirs lands, alongside the two handover
  `05B` §4 already owes. Needing to say this in prose instead of filing it — and having the pre-commit
  gate correctly *refuse* an earlier draft of this Report for naming their unlanded id — is itself more
  evidence for the `xtask register-loose-end` those two owed rows are about.
- **Actuation from a task in its own address space.** `FEAT-P1-03` composes with this and the Feature
  deliberately does not gate on it.
- **Any timing baseline or gate.** No `goals/performance/baselines/` entry, no `check-timing-regression`
  step, and `--update-baseline` was never invoked (`LE-28`). The ratio gate's reference loop belongs to
  `fixture-measure`; a second reference would drift against the first, which that gate's own doc comment
  warns about at length.
- **Clippy was not run workspace-wide on the authoring host.** `hal-x86_64`'s
  `boot`/`interrupts`/`qemu_exit`/`serial` modules are `#[cfg(not(target_os = "windows"))]`, so
  `cargo clippy --workspace --all-targets` cannot build the `no_std` binaries on Windows — a pre-existing
  condition, not introduced here. Clippy was run against the real target instead, with each fixture
  feature enabled, and is clean; CI runs the workspace form on Linux.
