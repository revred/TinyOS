**Deliberately not done:**

- **No storage-backed journal.** This kernel has no filesystem yet — `SpoorJournal<N>` is an in-memory ring buffer only. `JOURNAL_MAGIC` is defined so a future storage-backed journal can serialize this buffer's contents directly (magic header, then each entry's `to_bits()` value in oldest-to-newest order) without a translation step, but no such serializer exists yet.
- **No real concurrency test.** This kernel's current execution model is single-CPU with no interrupts yet (no timer/IDT — a gap named repeatedly across recent handovers), so "an in-progress `append` is atomic with respect to any concurrent read" (the Story's own acceptance criterion 2) is satisfied by Rust's own borrow-checker guarantee (no concurrent `&mut self`/`&self` access is even expressible through the safe API), not by a constructed multi-threaded/interrupt-driven race test — there is no such execution context available yet to construct one against.
- **No subsystem wired to actually call `append`.** Per `FEAT-P0-06`'s own exit criteria, this is tracked as a separate follow-up (natural candidates: `kernel::lock`'s boost/restore events, `kernel::wcet`'s overrun detection), not part of this Story's own acceptance criteria.
- **No query/replay/summarize API.** `Sharc.Blue`'s own `spoor.query`/`spoor.watch`/`spoor.replay`/`spoor.summarize` atoms are deliberately out of scope for Phase 0 — TinyOS has no shell/tooling layer yet to host such commands (`EPIC-P2`, Phase 2 — Shell & UX).
