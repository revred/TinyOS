## Security and performance interpretation

- Tauri, Wails, .NET, Node, Bun, Chromium, games, TinySpot, the TinyOS Linux Environment, Windows TinyOS Tools, browser-hosted TinyOS, and fleet workloads are **optional profiles**, never additions to the 8 MiB core image by definition.
- A runtime's own permission model is defense in depth, not a TinyOS security boundary. Every runtime remains inside a Protection Domain with private active memory, kernel-owned capabilities, bounded IPC, provenance, budgets, and teardown.
- .NET/C# is not categorized as inherently unsafe. Production C# support is `managed-aot`: self-contained Native AOT first, no `Reflection.Emit`, unrestricted assembly loading, generic process injection, COM/remoting, or unrestricted/name-only P/Invoke. Native interop targets must be independently admitted and content-addressed.
- JavaScript code generation, native addons, FFI, inspectors, package lifecycle scripts, browser renderers, game downloads, mods, and server-provided content remain absent, separately brokered, or C4-hostile input until their exact charter gates are earned.
- “10×,” “bare-metal equivalent,” “highest tokens/s,” “one-tenth time-to-quality,” hard-real-time, and browser-security-equivalence statements remain claim gates requiring comparable raw evidence; no such performance result is claimed here.

## Current implementation boundary

The newest code provides a real 256-entry IDT, legacy-PIC retirement, local-APIC timer bring-up, bounded local channels, and generation-safe transactional shared-memory grants. It still lacks active per-task `CR3`, domain-aware `#PF`/`#GP` termination, TSS/IST, production capability spaces, executable sealing, IOMMU isolation, TCP/IP, GPU/display/audio services, runtime hosts, and hostile-campaign evidence. All affected rows therefore remain roadmap context, not Verified runtime capability.
