## The tolerance model, and the two constants it took to get right

This is the part of the Story that produced a real result rather than a mechanism, so it is recorded in the order it happened.

**Draft 1 — 20% relative, 8-cycle floor.** Chosen from `REPORT-2026-07-27-02`'s finding that `min`/`p50` were the *stable* statistics. Then five consecutive release-profile runs were measured, and the gated statistics turned out to move far more than "stable" implied. Worst run's excess over the five-run median:

| Metric | `min` spread | `p50` spread |
|---|---|---|
| D04 context switch | 218–292 (+11% over median) | 226–338 (**+23%**) |
| D05 dispatch round | 408–498 (+19%) | 430–548 (**+25%**) |
| D05 select | 68–80 (+14%) | 72–84 (+14%) |
| D07 alloc/free | 62–84 (+8%) | 68–110 (**+28%**) |
| D07 denial | 8–26 (+117%, but +14 *cycles*) | 10–30 (+67%, +12 cycles) |

A 20% tolerance would have failed green code on its first CI run.

**Draft 2 — 40% relative, 24-cycle floor**, which clears every row above. It was then falsified by its own first gate run: D07 alloc/free's `min` came back **92 against a 66 baseline — +39%, landing exactly on the limit**. Not a regression; the same code, minutes later, on a shared unpinned Windows host under TCG.

**Committed — 60% relative, 24-cycle floor.** Wide enough to clear a +39% excursion with margin. The floor exists because percentages stop meaning anything on a 12-cycle metric (3 cycles would be a 25% "regression").

**What that costs, stated rather than buried:** at Tier 0 this gate catches regressions of roughly **1.6x or worse**. It is a tripwire for an accidental O(n) in a selection loop or a lock added to an RT path. It is **not** a defense against a 10% creep, and no honest choice of constant makes it one on TCG. That is a measured property of the emulator, and it is the most concrete argument this Epic has yet produced for `LE-09`'s hardware tier.

## The gate, *failing* — the criterion this Story exists for

`--inject-regression` builds with `fixture-measure-regression`, which performs seven extra `highest_priority_ready` selections **inside the timed region** of the D05 selection phase. Real measured code, in a never-shipped Cargo feature, following `fixture-broken-boot`'s precedent — not a doctored baseline file, which would prove only that the arithmetic works:

```
$ cargo run -p xtask -- check-timing-regression --runs=3 --inject-regression
  D05/dispatch_select_highest_priority_ready min baseline=74  observed=1048 limit=118 REGRESSED
  D05/dispatch_select_highest_priority_ready p50 baseline=76  observed=1086 limit=121 REGRESSED
  D04/context_switch_yield_roundtrip_2switches min baseline=216 observed=212 limit=345 ok
  D07/pool_u64x64_alloc_free_round_trip      min baseline=66  observed=64   limit=105 ok
  ...
xtask: 2 gated statistic(s) regressed beyond tolerance
GATE_EXIT=1
```

~14x over baseline, caught, named, with baseline/observed/limit printed — and, importantly, **the other four metrics still passed**, so the gate localizes rather than smearing.

## `LE-09` piece 4, and why it was cross-checked rather than trusted

The verdict line is new machinery, and new machinery that reports "pass" is exactly the machinery you should not trust. So on Tier 0 both signals are read and **must agree**: a UART `ok=true` against a QEMU failure exit code (or the reverse) is a harness error naming both. Every run in this Report exercised that agreement. When the Pi 5 arrives, the UART bit will be the only bit there is — and it will arrive already cross-checked against an independent signal on another architecture, rather than being trusted for the first time on the day it becomes load-bearing.

## What this Report does not establish

- **No hardware tier.** Everything here is Tier 0 QEMU/TCG. `LE-09` stays open and release-blocking.
- **No `PERF` guardrail closes.** A baseline records what this code does today under emulation; it is not a WCET, not a budget, and not a contract with any caller.
- **No tail gating.** p99/p99.9/max are reported and deliberately ungated, and `LE-15` warns that the hardware tier's noise has a different shape (quantization, not jitter), so today's tolerances will not transfer to it unchanged.
- **The gate's own sensitivity is poor**, by measurement rather than by choice: ~1.6x at Tier 0. Anything finer needs the board.
