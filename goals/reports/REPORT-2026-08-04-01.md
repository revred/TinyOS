## Result

**Pass.** A hardware tier exists: `fixture_measure` ran to completion on a Raspberry Pi 5, emitted a complete `TOS64-MEAS/2` envelope of eight metrics at `n=1000 dropped=0 warmup=100`, and the numbers in it are the first in this project's history that are about TinyOS on silicon rather than about QEMU. **`LE-09`, `LE-15`, `LE-24` and `LE-27` close on this Report**, each on the specific evidence quoted below. Assurance state stays `baseline-debt` throughout: no `PERF-*` release gate closes, no Story becomes assurance `verified`, and no guardrail-evidence row is filed — a bring-up measurement is not a release-gate run in a declared deployment profile.

Every metric `n=1000 dropped=0 warmup=100`. Verdicts 5 and 6 carry the same envelope shape from the same image lineage; run-to-run agreement across the three measure boots is a few cycles on six of eight metrics (context switch 80/80/80, per_op_of_8 480/479/480, dispatch_select 1525/1532/1532). `fault_brk_capture` is the least repeatable (109/120/111, ~10%) and is the metric to distrust first if any absolute `D02` figure is ever quoted.

**Batch policy, per metric (criterion 2):** the denial metric keeps its recorded batch of 64; the round-trip twin uses 8 — large enough that the calibrated subtraction stops being the whole answer, small enough to stay near the batch-of-1 regime the recorded 607-vs-58 superlinearity finding indicts at 64; every other metric is unbatched with `PMCCNTR_EL0` as the source. The batch is carried in the metric *name* (`_per_op_of_N`), so the parser needed no new key.

**Which pool number is quotable — the `LE-24` result (criterion 3):** `kernel::measure_phases::phase_pool_alloc_free_batched` records `cycles / ROUND_TRIP_BATCH`, so 480 is already per-op — and it is *higher* than the unbatched 374–383 for the identical operation. Batching cannot make an operation slower; what it changes is the share of calibration residue each op carries. The ~100-cycle gap is residue the unbatched shape was silently crediting to the pool — `LE-24`'s exact thesis, observed on silicon. **The board's quotable `D07` round trip is 480 cycles/op; the unbatched figure must not be quoted as a result.** The same suspicion attaches to every unbatched metric above: relative comparisons between them survive; absolute per-op claims do not, until each has a batched twin or the residue is bounded. The host half of the pair: on the Windows dev host whose median-0 is `LE-24`'s subject, the batched twin medians **35 cycles/op (release, 3 runs, min 33)** and is gated, with the eighth baseline row added 2026-08-04 and none of the seven existing rows re-recorded. The two halves are **not** a like-for-like pair (x86_64 desktop vs 2.4 GHz A76, build profiles not confirmed identical); both are recorded with provenance and no ratio is derived.

### The MMU and the cache probe (`TEST-P1-07-03-A`; `BOARD VERDICT 5`, kernel `0c709197ed26`)

```
TOS64-MMU/1  SCTLR=0000000030D01805 OFF=75213055 ON=183180
```

`SCTLR_EL1` read back — not assumed from the write — with `M` (bit 0), `C` (bit 2) and `I` (bit 12) set. The same loop through the same memory: 75,213,055 cycles through Device memory, 183,180 with caches on — **410×**. Verdict 7 repeats it at ~405×. Every measurement in the envelope above is taken with caches on and is therefore about TinyOS, not the bus.

The fault half (`BOARD VERDICT 8`, kernel `fde0f2ce3f91`, `mmu-fault` fixture):

```
TOS64-FAULT/1 SLOT=CUR_EL_SPX/SYNC INDEX=04
TOS64-FAULT/1 ESR=0000000096000005 CLASS=DATA-ABORT EC=25 IL=32
TOS64-FAULT/1 STATUS=TRANSLATION LEVEL=1 WNR=READ ISV=NO SIZE=UNKNOWN S1PTW=NO
TOS64-FAULT/1 FAR=0000002000000000 ELR=000000000008EF08 SPSR=0000000040000345
TOS64-FAULT/1 HALTED REASON=NO-RESUME-PATH
```

`FAR_EL1 = 0x20_0000_0000` — the unmapped guard address to the bit. `ESR` decodes internally consistently (`EC=0x25` data abort from EL1, `DFSC` translation fault level 1, `WnR=read`, `ISV=0` so `SIZE=UNKNOWN` honestly rather than guessed). `HALTED REASON=NO-RESUME-PATH` is fail-safe-over-keep-trying on silicon: slot 4 has no resume path, so the handler reported and stopped. `SPSR.I=0` independently corroborates `STORY-P1-07-10`: interrupts were unmasked at the fault, from a code path that was never asked about it. This frame also satisfies `STORY-P1-07-02`'s decoded-`ESR` clause on the proven canvas channel (serial has never produced a byte on this bench, `LE-47`).

### The timer, the counters, and the `LE-15` decision (`TEST-P1-07-04-A`)

```
TOS64-CONF/1 CNTVCT=PASS SPAN=168 CNTFRQ=54000000 CPUS=54          (verdict 5)
TOS64-PMU/1  DELTA=24000227 RATE=2400MHZ SOURCE=PMCCNTR            (verdict 5)
TOS64-TICK/1 COUNT=1816 TVAL=540000 RMIN=999 RMAX=1000             (verdict 7)
```

- **`LE-27`'s subject executed on silicon:** `CNTVCT_EL0` monotonic over the sample window, `CNTFRQ_EL0` reads the architectural 54 MHz (`CPUS=54` is cycles-per-microsecond, *not* a core count — recorded because the field name invites the misreading), and `PMCCNTR_EL0` counts at the A76's 2.4 GHz core clock.
- **`LE-15`'s recorded decision procedure ran on the device it was written for:** probe `PMCCNTR_EL0` against the generic timer, choose by measurement. It chose `PMCCNTR` at 2400 MHz. The 54 MHz counter question ("decide when a board exists") is decided — by the board.
- **The tick:** `COUNT=1816` at `TVAL=540000` (= 54,000,000/100, the declared 100 Hz) over ~18 s, with `RMIN=999 RMAX=1000` per mille — every pair of consecutive intervals agrees to within 0.1%, judged by ratio and never by absolute value, exactly as the criterion required. Getting here surfaced and cured two defects that were invisible to every host gate: `LE-69` (a constant asserting five implemented GIC priority bits refusing BCM2712's conformant four — cured by *discovering* the width, not by swapping the constant) and `LE-71` (the fixture's interrupt mask had no counterpart, so criterion 1 was unsatisfiable on any board — cured by `STORY-P1-07-10`, and the verdict-6 outlier `max=3519` that the single pre-mask tick caused is absent in verdict 7, `max=376`).

## Reproducibility metadata (criterion 4)

- **Board:** Raspberry Pi 5 Model B Rev 1.1, BCM2712 (4× Cortex-A76 r4p1, `0x414fd0b1`), 16 GB. Read from the same board's Pi OS ground-truth boot in the evidence register.
- **Firmware:** bootloader EEPROM `086b83e3332dfc8927c56762771d082f3077a1ae` (release), 2026-05-26T15:01:25 UTC, variant `start_cd`; `BOOTLOADER: up to date` at capture time.
- **Clock policy:** TinyOS programs no clocks and runs no governor; the firmware's handoff state is what was measured. Measured on silicon rather than assumed: `CNTFRQ_EL0=54000000` and `PMCCNTR_EL0` at 2400 MHz against the generic timer (`DELTA=24000227` over the probe window). No throttling instrument existed in these images.
- **Thermal state:** **not measured.** These images carried no thermal sensing at all (`LE-75` was raised for exactly this on 2026-08-05; the first thermal-sampling image `f06bfa8ac7ec` postdates every run quoted here and has never booted). Runs were 30–90 s from cold on an open bench; nothing here supports any claim about sustained operation. A stated "not measured" is the criterion's own requirement; it is not a pass of the thermal clause of the measurement protocol.
- **Configuration:** single core (cores 1–3 parked), IRQs masked inside measured regions per `STORY-P1-07-10`'s scope discipline, caches on, `n=1000 warmup=100` per metric.
- **Known variation:** ~3% build-to-build movement on untouched code paths (`BOARD VERDICT 9`: round trip 374→361, dispatch_select 1532→1503 across a binary change that did not touch them) — almost certainly code layout. **No figure in this Report should be quoted to better than ~3%, and no timing gate should be set tighter.**

## What these numbers are **not** (criterion 4's list, stated so it can be quoted with the numbers)

- **Not a bound.** Per `ADR 0005`: a measurement establishes the *tier*; a worst-case latency bound, WCET claim or jitter envelope is quotable only from a platform holding a secure-world qualification record, and **no platform holds one — the Pi 5 included** (`qualified-platforms.tsv` count: zero; the envelope's own `qualification=none` says so at the moment of measurement). No `TOS64-BOUND/1` claim is filed and no `G04` row can cite this Report.
- **Not a release gate.** `PERF-Dnn` guardrails close on a release-gate run in a declared deployment profile. No guardrail closes here and no guardrail-evidence row is filed.
- **Not a comparative claim.** `G24`/`G25` run only after absolute gates pass, same hardware, safety-equivalent configuration. Nothing here licenses "faster than X".
- **Not `EPIC-P1` at large.** Single core, no preemption, no per-task address spaces, no `EL0`, no WCET enforcement, no verified boot (`SEC-01` selected so its absence is named: the Pi 5 firmware chain gives TinyOS no measured-boot evidence, and `BND-01` stays open).
- **Not free of residue.** Only the batched `D07` twin (480 cycles/op) carries a bounded calibration residue; the six unbatched metrics carry an unquantified one of the same kind.
